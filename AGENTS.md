# Reglas del Proyecto — Control de Versiones y Trabajo Local

## ⚠️ Regla Estricta de Git y Trabajo Local

1. **PROHIBICIÓN ABSOLUTA DE `git push` AUTOMÁTICO**:
   - Está terminantemente prohibido ejecutar `git push` por iniciativa propia, como paso previo/posterior o como automatización de cualquier tarea.
   - Todo trabajo se realiza, prueba, compila y valida **exclusivamente de manera local**.

2. **AUTORIZACIÓN EXPLÍCITA REQUERIDA**:
   - Solo se ejecutará `git push` a cualquier rama remota (`origin/front-back`, `origin/main`, etc.) cuando el usuario lo solicite de manera directa y explícita en el chat (ej. *"haz push"*, *"manda el push"*, *"sube los cambios a github"*).

3. **CONFIRMACIÓN PREVIA**:
   - Si una tarea requiere compartir cambios, el agente debe informar que los cambios están listos localmente y esperar la instrucción directa del usuario antes de tocar el repositorio remoto.
